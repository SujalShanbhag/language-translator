LANGUAGE TRANSLATOR
USER MANUAL

1. ABOUT THIS TRANSLATOR

This Language Translator is a web application built with HTML, CSS, JavaScript, and Python.

It allows you to:
- Enter or paste text.
- Select a source language.
- Select a target language.
- Translate text.
- Enter text using the microphone.
- Copy the translated result.
- Listen to the translated result with server-side text-to-speech.
- Load the current language catalog dynamically.

The application does not contain a manually maintained list of translation languages.

2. HOW THE APPLICATION WORKS

The application has two parts.

FRONTEND
The browser uses HTML, CSS, and JavaScript to display the translator and handle:
- Language selection.
- Text input.
- Microphone speech recognition.
- Translation requests.
- Copying the result.
- Playing generated speech.
- Loading the user manual.

PYTHON API
The Python API runs as a Vercel serverless function. It:
- Retrieves the current translation-language catalog.
- Sends translation requests to the translation provider.
- Checks the requested languages against the live catalog.
- Splits long input into smaller translation requests when necessary.
- Generates server-side speech using dynamically available voices.
- Returns clear errors when a service does not provide a verified result.

3. HOW TO USE TEXT TRANSLATION

Step 1: Open the deployed translator.

Step 2: Select the Source Language. This is the language of the text you are entering.

Step 3: Select the Target Language. This is the language you want as the result.

Step 4: Type or paste text into the input box.

Step 5: Click Translate.

Step 6: Wait for the translation to finish.

Step 7: The translated result appears in the output box.

If the translation provider fails or returns an invalid/empty response, the application shows an error instead of displaying an unverified translation.

4. SOURCE LANGUAGE

The Source Language describes the language of your input.

Example:
Source Language: English
Input: Hello, how are you?

Select English when the input text is English.

5. TARGET LANGUAGE

The Target Language describes the language you want for the translated result.

Example:
Source Language: English
Target Language: Hindi

The application requests an English-to-Hindi translation.

6. HOW TO USE THE MICROPHONE

The microphone converts your speech into text before translation.

Step 1: Select the Source Language.

Step 2: Click the microphone button.

Step 3: Allow microphone permission if your browser asks for it.

Step 4: Speak clearly.

Step 5: The recognized speech appears in the input box.

Step 6: Select the Target Language.

Step 7: Click Translate.

The speech-recognition language is taken from the currently selected source language. The project does not use a manually hardcoded speech-language table.

Microphone recognition depends on browser support and microphone permission. A current Chrome or Edge browser is recommended.

7. SPEECH TRANSLATION WORKFLOW

The complete process is:

Your speech
    ↓
Browser speech recognition
    ↓
Recognized text
    ↓
Input text
    ↓
Python API
    ↓
Translation provider
    ↓
Translated text
    ↓
Output

The microphone recognizes speech. The translation service translates the recognized text.

8. HOW TO COPY THE RESULT

After a translation appears:

Step 1: Click Copy.

Step 2: The translated text is copied to your clipboard.

Step 3: Paste it into another application if required.

Clipboard access depends on browser permissions.

9. HOW TO USE SPEAK

The Speak button generates audio from the translated result using the Python server.

Step 1: Translate your text.

Step 2: Make sure the translated result is visible.

Step 3: Click Speak.

Step 4: The server checks the available voices dynamically.

Step 5: A voice matching the selected target language is selected.

Step 6: Audio is generated and returned to the browser.

Step 7: The browser plays the audio.

The project does not contain a hardcoded voice-language table.

If no working voice is available for the selected language, the application reports the problem instead of speaking the text using an unrelated language.

10. TRANSLATION AND SPEECH ARE SEPARATE

Translation:
Input text → translated text

Speech:
Translated text → audio

Therefore, translation can work even when the speech service is temporarily unavailable.

11. LANGUAGE LIST

The translation language catalog is obtained dynamically from the online translation service.

This means the project does not depend on a manually written list of language names and codes.

The language catalog and the server voice catalog are separate. A language may be available for translation but not have a matching server voice.

12. USER MANUAL

Click User Manual in the application to open this documentation.

The application loads the manual from its own deployed project files through the Python API. It does not depend on a hardcoded deployment domain.

13. ERROR HANDLING

Possible messages include:
- Translation service unavailable.
- The selected language is not currently available.
- No verified translation was returned.
- Microphone permission was denied.
- Browser speech recognition is not supported.
- Server voice could not generate audio.
- No working server voice was found for the selected language.

When translation fails, the application does not replace the failed result with an unrelated or unverified translation.

14. INTERNET REQUIREMENT

An internet connection is required for the online translation and server voice services.

The deployed application itself is hosted on Vercel, while translation and speech generation communicate with their online providers.

Temporary external-provider failures cannot be eliminated by application code. The application handles such failures by reporting them clearly.

15. VERCEL DEPLOYMENT

This version is structured specifically for Vercel.

The project contains:
- public/index.html
- public/style.css
- public/app.js
- public/manual.txt
- api/index.py
- requirements.txt
- vercel.json

Vercel automatically serves the frontend files and runs api/index.py as the Python API.

No production domain is written into the frontend code.
No production port is written into the frontend code.
No production API URL is written into the frontend code.

The frontend communicates with the Python API using same-origin relative paths such as /api/languages, /api/translate, and /api/speak.

No environment variables are required by this project.

16. DEPLOYMENT STEPS

Step 1: Upload the project to GitHub.

Step 2: Import the GitHub repository into Vercel.

Step 3: Make sure the selected project root contains the api and public folders and requirements.txt.

Step 4: Deploy the project.

Vercel installs the Python dependencies and creates the Python serverless function automatically.

17. AFTER LONG INACTIVITY

Vercel may start a new serverless function instance after a period of inactivity. This is normal serverless behavior.

The application does not require a permanent running Python process, permanent local memory, or a manual server restart. Language and voice information can be loaded again when a new function instance starts.

The application therefore does not depend on a continuously running local server.

External services can still have their own availability, rate limits, or temporary failures. Those conditions are outside the application's control.

18. NO HARDcoded DEPLOYMENT ADDRESS

The application does not require you to edit a domain name after deployment.

API requests are relative to the current website, so the same project can run on the Vercel deployment address or a custom domain without changing the JavaScript API paths.

21. IMPORTANT NOTES

- Do not open the HTML file directly as a local file when testing the complete application.
- Use the Vercel deployment for production.
- Use a current browser for microphone support.
- Allow microphone permission when required.
- Keep an internet connection available for translation and server speech.
- Select the correct source and target languages.
- Do not expect every translation language to have a matching speech voice.
- If an external service temporarily fails, retry later.

22. SUMMARY

This translator provides a complete text and speech-assisted translation workflow.

It dynamically obtains translation languages, accepts typed or microphone-generated text, sends the text through the Python API, displays the translated result, allows the result to be copied, and can generate server-side speech when a suitable voice is available.

The application is designed for Vercel serverless deployment and does not require a permanently running Python server, a hardcoded production domain, or a hardcoded production port.
